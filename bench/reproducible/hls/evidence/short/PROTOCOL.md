# Linux DEV HLS proxy comparison, 28 November 2026

Each simulated viewer requests a 3,000,000-byte HLS segment every 6 seconds (4 Mbps). HTTP/1.1 TCP loopback. Synthetic RAM origin, fresh processes per arm, no CDN, hop encryption or network bandwidth claim. The same hash-pinned binary supplies the origin and downstream load for every arm. Proxy CPUs 12–13, origin 8–11, load 4–7, coordinator CPU 2, unchanged host and service settings. Proxy process CPU 100% means one vCPU. Go binaries use GOMAXPROCS=2 for the proxy and are built with Go 1.26.11. Actix uses two workers.

The arm order starts with Kruda v1.9.0 + experimental pooled 256 KiB copy buffer, StreamKeepAlive, and TIINNO_BENCH_WING_COPY_256=1; Fiber v3.7.0 / fasthttp v1.78.0 via SendStream; Actix Web 4.20.0 / Reqwest 0.12.28 via per-worker upstream clients and Actix 32 KiB HTTP/1 write-buffer setting. Those buffer settings control different implementation seams. Compare configured proxy stacks using the same external contract. Reuse comparator builds from the 9,472-viewer experiment. Exact executable digests and local source pointers accompany the results.
